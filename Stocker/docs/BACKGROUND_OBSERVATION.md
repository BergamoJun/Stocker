# BE 최초 예측 결과의 자동 관찰

사용자가 2026-11-07에 요청한 자동 관찰 작업을 Windows 작업 스케줄러에 등록했다. 채팅이나 IDE를 열어 둘 필요가 없다. 이 작업은 기존 예측을 실제 가격과 비교하며 매매 주문, 새 예측 생성, 뉴스 조회, ML 학습을 수행하지 않는다.

## 언제 무엇을 실행하는가

- 작업 이름: `Stocker-BE-Outcome-4075ad8deab9133e`.
- 최초 실행: **2026-11-14 14:02 한국 시간**, UTC 05:02.
- 대상: 11월 9~13일의 미국 정규장 5거래일을 관찰하도록 미리 저장한 BE 가격 예측과 비용·위험 판단. 같은 관찰 기간의 기존 ATR 비교 기록도 평가한다.
- 실행 방법: 현재 Windows 사용자·일반 권한의 `pythonw.exe`. 창을 띄우지 않으며 비밀번호를 저장하지 않는다. API 키는 실행 시 기존 사용자 환경변수에서 읽고 파일·명령행·로그에 저장하지 않는다.

무료 일봉 제공 시각을 기다리기 위해 원래 기록에 남긴 조회 예정 시각을 사용한다. 가장 빠른 확정된 실적 결과 시각은 아니며 공급자 지연이 있으면 늦어진다.

PC가 켜져 있고 해당 Windows 사용자가 로그인한 상태여야 실행한다. 화면 잠금 상태에서도 로그인 세션이 유지되면 실행할 수 있다. 절전 해제 요청과 예약 누락 시 따라잡기를 설정했다. 절전 해제는 하드웨어·전원 설정의 영향을 받으며 전원이 꺼진 PC를 켜는 기능은 아니다. 예약을 놓쳤다면 다음 사용 가능 시점이나 다음 로그인에 실행한다.

## 지연·장애·중복 실행은 어떻게 처리하는가

한 번 실행할 때 새 무료 가격 요청은 최대 1회다. 이미 필요한 최신 가격이 정상 저장돼 있으면 그것을 사용한다. 지연 시 15분 간격으로 재시도하며 첫 실제 예약 후 실행부터 24시간, 최대 97회 요청 한도를 둔다. PC가 꺼져 있었다는 이유로 실행하기 전 재시도 시간을 소진하지 않는다.

스케줄러는 같은 작업의 겹친 실행을 무시하고, 작업 내부도 프로세스가 종료되면 풀리는 파일 잠금을 사용한다. 성공한 결과는 덮어쓰지 않고 이후 실행에서는 API를 다시 부르지 않는다. 완료 또는 입력·사용권·규칙의 중대한 오류, 재시도 한도 도달 시 자기 작업만 비활성화한다. 비활성화가 실패해도 저장한 종료 상태 때문에 API를 반복 호출하지 않는다.

첫 요청 전 원래 예측 파일, 계산 코드, 정책, 스키마, 저장된 사용권의 해시를 확인한다. 해시는 내용이 바뀌었는지 확인하는 식별값이다. 원본 가격 이력의 수정이나 관측 시각의 모순도 기존 사후 평가 규칙으로 검사한다. 다른 정책으로 바뀐 결과를 원래 예측의 성과로 계산하지 않는다. 변경을 발견하면 보류하고 기록한다.

지정한 기존 기록만 평가하며 더 유리한 새 예측으로 교체하지 않는다. 5거래일이 모두 실제로 관측되기 전에는 현금 선택의 0 수익도 완료 결과로 만들지 않는다. 수익은 거래 비용을 가정한 가격 계산 결과이며 실제 증권 계좌의 체결 수익이 아니다.

## 어디서 상태와 결과를 읽는가

현재 작업 폴더는 `reports/private/observation_jobs/4075ad8deab9133e/`다.

- `status.md`: 사람이 읽는 현재 상태. 지금은 예약 전 대기다.
- `state.json`: 요청 횟수·마지막 확인 시각·완료/보류 상태.
- `job.json`: 고정 대상·실행 시각·원본과 코드/정책 해시.
- `scheduler_registration.json`, `task_definition.xml`: 실제 Windows 등록 정보.
- `runs/`: 작업 처리 기록. 예약 전 조기 확인은 상태 파일에 남긴다.
- `result/report.md`, `result/observation.json`: 실제 관찰을 마친 뒤 생성할 결과. 아직 존재하지 않는다.

결과 보고서는 예상 고점 구간과 실제 최고가, 예상 형성일과 실제 형성일, 비용 후 가상 손익, 최초 비용·위험 판단의 선택, 같은 기간 단순 보유 손익을 설명한다. 같은 일봉에서 목표·손실 기준에 모두 닿으면 임의로 순서를 정하지 않고 손익 범위를 남긴다. 관찰은 같은 한 주의 한 건이며 여러 계산 기록을 독립 표본 여러 건으로 세지 않는다.

## 실제 설정 확인 결과

등록 상태 Ready, 다음 실행 2026-11-14 14:02 KST를 확인했다. 스케줄러에서 직접 시험 시작해 **종료 코드 0**, **예약 전 대기**, **가격 API 요청 0회**, **사용자 키 접근 가능**을 확인했다. 이 시험은 예약 프로그램의 동작 검사이며 미래 수익 결과를 관측한 것이 아니다.

설치 코드는 `scripts/install_observation_task.ps1`, 실행 코드는 `research/observe.py`다. 새 작업 준비에는 `python -m research.observe --prepare`를 사용한다. 현재 작업 검사는 아래처럼 실행한다. 실행 환경의 사용자 환경변수 접근 제한 때문에 검사 도구의 키 표시가 달라도 실제 스케줄러 시험의 사용자 세션 결과와 구분한다.

```bash
python -m research.observe --job reports/private/observation_jobs/4075ad8deab9133e/job.json --check
```

계산 핵심 파일이 바뀌면 원래 방법론을 보존하는 별도 검토·작업 버전 등록이 필요하다. 해시만 새 값으로 고쳐 통과시키지 않는다. 독립 뉴스 보관 기능은 이 작업이 고정한 계산 파일을 변경하지 않는다.

첫 한 건의 결과만으로 예측력을 승인하지 않는다. 정식 투자 매력도·검증 ID는 보류하고 이후 사전 예측과 실제 결과를 누적한다. 월 데이터 예산 $0과 프로그램의 외부 LLM 호출·토큰 사용 0을 유지한다.
