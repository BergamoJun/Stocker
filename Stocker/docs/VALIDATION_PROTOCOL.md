# BE 가격 후보 평가와 다음 단계 실행

현재 범위는 개인용·월 데이터 예산 $0이다. 사용자는 주요 결정이 필요한 경우를 제외하고 다음 개발 단계를 계속 진행하도록 요청했다. 유료 플랜, 공개 배포, 외부 가격 LLM 입력, 미검증 추천 수치 활성화는 이 절차가 허용하지 않는다.

## 고정한 연구 규칙

`config/validation_protocol.json`의 BE-atr14-research-protocol-v1은 2026-11-07에 실제 가격 진단 결과를 계산하기 전에 등록했다. 후보 정책 파일의 SHA-256을 고정하며 파일이 바뀌면 평가를 거절한다. 입력·권한·프로토콜·계산 코드 해시를 먼저 등록하고 결과 파일을 새로 쓴다. 기존 결과를 덮어쓰지 않는다. 변경한 방법론은 새 버전/프로토콜로 다룬다.

가격 사전 진단은 최소 60세션 이력 뒤 5세션마다 한 사례를 만들고 다음 5세션의 라벨이 겹치지 않게 한다. 기존 규칙대로 시간순 앞 80%와 뒤 20%를 구분하며, 결과에 맞춰 배수/가중치를 조정하지 않는다. 현재 주식수 기준 ATR14·목표 +2ATR·무효화 -ATR 후보를 유지한다.

편도 10bp와 25bp를 각각 가정한다. 다음 정규장 시가가 목표/무효화 밖이면 진입 불가, 갭 하락은 시가, 같은 일봉에서 양방향 도달은 순서 불명으로 남긴다. 가격 조건이 성립하지 않는 사례도 제외하지 않고 별도 불가 사례로 기록한다. 비교 기준은 같은 해결 사례의 다음 정규장 시가→5번째 종가이며 같은 비용을 적용한다. 미해결 수·사유와 모든 사례의 비교 기준 수익률도 JSON에 보존한다.

연구 선별 기준은 해결 사례 30개 이상, 모호/진입불가/가격불가 비중 10% 이하, 비용 후 평균과 비교 기준 대비 평균 초과가 각각 0보다 큰지다. 두 비용 조건 모두에서 확인하며 훈련/평가 구간을 따로 표시한다. 이는 후속 검토를 위한 선별 기준이다. **기준 충족은 검증 통과나 추천 활성화를 뜻하지 않는다.** 한 종목·작은 평가 표본·배당/세금 제외·현재 수정 이력 한계가 남는다.

## 과거 진단과 당시 가용 자료의 구분

현재 확보한 BE 과거 가격은 현재 내려받은 수정 이력이다. 이 가격으로 계산 동작과 가격 후보의 사전 진단을 실행할 수 있지만 과거 시점 보존 검증으로 부르지 않는다. `load_diagnostic_snapshot`은 이 연구 전용 입력 경로다. 통화·조정·출처·권한·관측시각·세션 누락 검사를 유지하고 마지막 세션의 현재성 요구만 적용하지 않는다. 현재 가격 계획의 `load_price_snapshot`은 기존 최신성 조건을 그대로 유지한다.

사전 진단은 실제 available_at을 바꾸지 않는다. 가정한 판단 시각(hypothetical_decision_at), 라벨 기간 종료(label_period_ended_at), 실제 관측한 라벨 시각(label_available_at)을 구분한다. 결과는 retrospective_diagnostic_not_validation이며 현재 목표가·추천 점수·예상 도달기간·검증 ID는 모두 null이다. 뉴스 40% 모델이나 재무/기간 모델을 이 가격 진단으로 검증했다고 표시하지 않는다.

## 앞으로의 예측 기록과 사후 평가

최신 가격이 확보되면 당시 관측한 이력으로 연구용 목표 후보를 만들고 다음 정규장 시가 이전에 등록한다. 실제 등록시각과 기준시각 모두 다음 정규장 시작 전이어야 한다. 종목·기준 세션·프로토콜별 첫 기록만 남기며 이후 더 유리한 결과로 교체하지 않는다. 시점 보존이 미확인된 과거 이력을 시점 보존 자료로 승격하지 않는다. 이 경우에도 **새 예측을 실제 진입 시각 전에 기록했다는 사실**은 별도로 보존할 수 있다.

등록 파일에는 입력 snapshot/source IDs, 후보·프로토콜·코드 해시와 이력 값의 해시를 저장한다. 이후 5개 관찰 세션이 모두 종료되고 그 자료를 실제 조회한 다음에만 결과를 쓴다. 예측 시점 이력이 이후 수정됐다면 기업행동/수정주가 기준을 확인하기 전 결과를 보류한다. 이미 저장한 예측/결과는 덮어쓰지 않는다. 같은 숫자의 십진 표현 차이(1000과 1000.0)는 수정으로 처리하지 않는다.

앞으로 모은 사례 30개, 목표 도달 10개는 기간 모델 검토를 시작하기 위한 최소량이다. 그 수만 충족했다고 검증을 통과하지 않는다. 뉴스 원 발행/사건 시각·영향 검토 이력과 뉴스 없는 모델과의 동일 모집단 비교, 가중치/정규화 검토는 별도로 남는다. 저장소의 파일/검토 메타데이터는 독립된 타임스탬프 인증이나 법적 사용권 진위의 증명이 아니다.

연구 산출물 계약은 `schemas/validation_artifact.schema.json` 1.0.0이다. 런타임과 테스트에서 검사하며 미검증 추천 점수·검증 ID를 거절한다. 실제 투자 보고서 계약 0.2.0은 변경하지 않는다.

## 실행과 제한된 대기 프로세스

```bash
python -m research.advance --no-fetch --no-news
python -m research.advance
python -m research.advance --defer-until-price
```

첫 명령은 저장된 가격만 진단한다. 둘째는 현재 무료 플랜에서 받을 수 있는 최신 세션이 빠졌을 때만 가격을 한 번 받고 뉴스 메타데이터를 조회한 뒤 준비 상태를 생성한다. 기존 개인 계정 확인 기록을 재사용하지만 매 실행 시 유효기간·용도·비용을 다시 검사한다. 키는 실행 프로세스 환경변수에서만 읽는다. 원본 해시와 재정규화 결과를 대조해 저장된 가격 변경을 감지한다.

셋째는 위 작업 후 무료 제공 시각을 기다리는 **한 번의 추가 실행**이다. 최대 4시간 안의 ET 자정+2분까지만 대기한 다음 현재 가격 조회·사전 진단·가능한 향후 예측 등록·기존 예측 사후 평가·뉴스 갱신·준비 상태 생성을 한 번 수행하고 종료한다. 24시간 서비스나 매일 반복되는 작업은 아니다. 유료 대체나 자동 추천 활성화는 없다. 가격 최신성/권한/데이터 오류는 보류하며 제공 지연을 가짜 가격으로 채우지 않는다.

뉴스는 원문 링크 메타데이터만 수집한다. 15분 이내 네 주제의 전체 성공본은 재사용한다. 실패/부분 수집본도 15분 동안 재요청을 쉬되 실패 상태를 그대로 유지한다. 이것을 중립 뉴스나 점수 0/50으로 바꾸지 않는다. 기존 snapshot 시각·커버리지·점수 보류를 보존한다.

상태와 결과는 아래 개인 폴더에 저장한다.

- `reports/private/advancement/<실행시각>/progress.md`: 단계별 진행 상태
- 같은 폴더의 `price_diagnostic/retrospective_diagnostic.md`: 실제 가격 사전 진단
- `reports/private/prospective_ledger/<record_id>/forecast.json`, `outcome.json`: 향후 예측과 사후 결과
- `reports/private/advance_control/process_state.json`: 프로세스 상태, PID, 다음 실행시각
- `reports/private/advance_control/active.lock`: 중복 실행 방지

백그라운드 실행은 창을 숨기고 표준 출력/오류를 개인 로그에 저장한다. PC가 켜져 있고 프로세스가 살아 있어야 한다. 수면/종료/로그오프·네트워크 장애가 있으면 예정 시각에 완료되지 않을 수 있다. 중단하려면 process_state.json의 PID와 실행 명령을 확인한 뒤 해당 프로세스만 종료한다. 비정상 종료 후 lock이 남으면 그 PID의 실제 종료를 확인한 뒤 lock 파일 하나만 정리한다.
