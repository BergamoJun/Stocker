# BE의 가격·회사 실적·시장·뉴스를 함께 읽는 단계

후속 단계에서는 무료 연준·EIA RSS 보완 경로와 원문 검토 입력·후보 뉴스 점수 검사를 추가했다. [뉴스 사건 검토 방법](NEWS_EVENT_REVIEW.md)을 참조한다. 아래 최초 실행 기록과 사전 예측은 보존하며, 새 자료로 바꾸지 않는다.

이 단계는 “계산상 목표가가 있으니 매력적인 종목인가?”를 확인하기 위해, 가격 계산 주변의 근거를 한 문서에 연결한다. 회사의 사업 실적과 시장 환경을 함께 보여주되, 자료를 연결했다는 사실과 미래 주가 예측력이 검증됐다는 사실을 구분한다.

## 무엇을 평가하는가

| 항목 | 독자가 확인할 질문 | 사용 자료와 해석 범위 |
|---|---|---|
| 가격·비용·위험 | 목표까지 올랐을 때 비용을 빼고도 위험에 비해 이익이 충분한가? | BE 종가로 출발하는 기존 고정 통계 계산과 비용 필터. 다음 시가의 실제 체결 가격은 아직 모른다. |
| 회사 실적 | 매출이 늘었는가, 본업에서 이익이 남는가, 사업에서 들어온 현금으로 설비투자를 감당했는가? | 저장된 SEC 공시에서 검토한 수치. 매출 증가율·영업이익률·설비투자 후 현금흐름을 기간·단위·원문과 함께 표시한다. |
| 시장 환경 | 미국 대형주 시장의 최근 가격 흐름은 어떤가? | SPY ETF의 최근 종가와 20거래일 평균, 최근 5거래일 가격 변화. 미래 수익 예측이나 배당 포함 총수익률이 아니다. |
| 업종 환경 | 폭넓은 청정에너지 관련 기업의 가격 흐름은 어떤가? | PBW ETF에 같은 관측 규칙 적용. 연료전지 전용 지표가 아니며 BE 보유 여부도 가정하지 않는다. |
| 최신 뉴스 | 기업·업종·거시경제/정치·원자재 사건을 어디까지 확인했는가? | 주제별 조회 상태와 원문 링크. 기사 발행 시각·사건·영향 검토가 끝나지 않으면 점수에 반영하지 않는다. |

ETF는 여러 종목을 담아 거래소에서 사고팔 수 있는 상품이다. SPY와 PBW의 역할·거래소·통화·상품 분류는 `config/context_policy.json`에 고정했다. [SPY 운용사 설명](https://www.ssga.com/us/en/individual/etfs/state-street-spdr-sp-500-etf-trust-spy), [PBW 운용사 설명](https://www.invesco.com/us/en/financial-products/etfs/invesco-wilderhill-clean-energy-etf.html)을 근거로 선정했다. 두 상품의 흐름이 BE 주가와 같다고 가정하지 않는다.

## 계산값과 실제 결과의 차이

기본 엔진은 과거 가격의 변화폭으로 앞으로 5거래일에 가능한 가격 흐름을 만든다. 기간 전체에서 가장 높은 가격이 모이는 구간을 참고해 목표 후보를 계산한다. 첫 번째 작은 반등의 꼭짓점을 찾는 알고리즘은 아니다. 같은 흐름에서 목표와 손실 기준 중 어디에 먼저 닿는지도 계산한다. [기존 수식과 한계](PEAK_MODEL.md), [거래 비용을 뺀 판단 규칙](TRADE_SCREEN.md)을 유지한다.

이때 만든 수백 개의 가격 흐름은 실제 거래 수백 건을 검증했다는 뜻이 아니다. 모형이 계산한 평균 이익도 실제로 관측한 수익이 아니다. 실제 검증은 예측을 먼저 저장하고 이후 주가와 비교해야 한다. 기존 합성 실험과 표본 검토의 결과를 이번 단계에서 통과로 바꾸지 않았다.

현재 가격 심사는 매수와 매도 각각 0.25%(25bp)를 가정한다. 1bp는 0.01%다. 손익비는 예상 손실 1원당 예상 이익이 얼마인지 나타낸다. 비용 후 목표 이익, 손익비, 보수적으로 계산한 여러 가격 흐름의 평균 손익 등 기존 조건을 모두 검사한다. 수치 조건 통과도 전체 투자 추천 승인은 아니다.

## 무료 자료와 장애 처리

개인용 월 데이터 예산 $0을 유지한다. 새 가격 조회는 승인한 두 ETF만 허용하며 요청을 15초 간격으로 나눈다. 가격 원본의 해시(파일이 바뀌었는지 확인하는 식별값), 종목 분류, 같은 기준 거래일 여부, 본인 계정 사용권을 다시 확인한다. 기존 BE 가격 정규화와 평가 규칙은 변경하지 않았다.

GDELT 조회가 HTTP 429(요청량 제한)로 실패한 경우 성공한 빈 검색으로 바꾸지 않는다. 이번 실행에서는 회사 주제 1회가 429로 실패하고 나머지 3개 주제는 대기 상태로 처리됐다. 이어서 본인의 Massive Stocks Basic 계정에 포함된 [일반 뉴스 API](https://massive.com/docs/rest/stocks/news)를 BE 회사 뉴스의 보완 경로로 한 번 조회해 기사 메타데이터 1건을 확보했다. 별도의 유료 뉴스 상품은 사용하지 않았다. 공식 문서상 일반 뉴스 갱신은 시간 단위이며 실시간 보장이 아니다.

이 보완 경로는 회사 관련 제한된 검색만 수행한다. 업종·거시경제/정치·원자재 뉴스를 확인한 것으로 취급하지 않는다. 제목·원문 링크·출판사·공급자 표기 발행 시각만 남기고 본문, 요약, 이미지, 공급자 감정 판정은 버린다. 원문을 추가로 가져오거나 외부 LLM에 보내지 않는다.

뉴스 메타데이터의 조회 후 30분을 최신 확인 기준으로 사용한다. 이 시간은 기사의 실제 발행/사건 시각이나 공급자 갱신 속도가 아니다. GDELT의 최초 발견 시각과 공급자가 표기한 발행 시각을 원문의 검증된 발행 시각으로 바꾸지 않는다. 같은 링크를 여러 공급자에서 찾으면 한 기사로 합치되 주제별로 실제 최신 조회가 있었는지 보존한다. 제목이 최신이라는 이유만으로 추천 점수에 가산하지 않는다. 기존 뉴스 가중치 40%도 바꾸지 않았다.

현재 보고서의 강조 링크는 **추가 검토할 원문**이다. 영향이 확인된 중요 호재·악재 목록은 아니다. 회사 실적도 저장 공시의 선택 수치이므로 최신 공시가 더 없는지 자동 확인한 결과라고 설명하지 않는다. 사용하지 못한 자료는 0점이나 중립 대신 “확인하지 못함”으로 표시한다.

## 예측을 먼저 저장하고 이후 결과를 비교한다

`context_journal`은 가격·비용 판단과 그때 확인한 근거 파일을 다음 정규장 시작 전에 저장한다. 같은 기준일·정책·엔진의 기록이 이미 있으면 덮어쓰지 않는다. 지금 보고서를 다시 생성해도 첫 기록에 나중 뉴스를 붙여 과거 판단을 바꾸지 않는다.

기존 가격 예측 기록의 파일 해시·정책·가격 계획이 일치해야 연결한다. 이후 결과를 계산할 때 근거 파일이나 정책이 바뀌었으면 보류한다. 5거래일의 가격이 모두 관측된 뒤에만 결과를 저장한다. 아직 기간이 끝나지 않았거나 미래에 조회한 자료라면 성공·실패로 계산하지 않는다. 가격 조건이 미충족된 경우의 가상 선택은 ‘거래하지 않음’이며, 그 경우의 0 수익 역시 관찰 기간이 끝난 후에만 기록한다.

첫 실제 관찰 기간은 **2026-11-09~2026-11-13의 미국 정규장 5거래일**이다. 무료 일봉 자료는 가장 빨라도 **2026-11-14 14:02 한국 시간** 이후 결과 조회 대상으로 잡는다. 제공자 지연이 있으면 더 늦어진다. 현재 이 단계에서 실제 결과까지 확인한 기록은 0건이다. 첫 한 건의 결과만으로도 예측력이 검증되지는 않는다. 지속적으로 사전 기록과 결과를 누적해야 한다.

## 실행과 산출물

Stocker 폴더의 가상환경에서 실행한다. 새 네트워크 조회와 저장 자료를 이용한 보고서 생성을 분리한다. 본인 계정 확인 기록과 `MASSIVE_API_KEY`가 필요한 조회 경로는 기존 개인용 설정을 사용한다.

```bash
python -m research.fetch_context
python -m research.massive_news
python -m research.context_report
```

마지막 명령 자체는 네트워크를 호출하지 않는다. 저장된 BE 가격이 최신 거래일 자료여야 하며, 뉴스 확인 시각이 오래됐으면 그 한계를 표시한다. GDELT는 기존 공유 호출 제한과 대기 규칙을 유지하며, 이번 실패 직후 추가 재시도를 하지 않았다.

- `reports/private/context_report/<시각>/report.md`: 새 독자가 읽는 보고서. 평가 목적·단위·판단 이유·자료 한계·다음 확인 일정을 설명한다.
- 같은 폴더의 `evidence_context.json`: 당시 연결한 공시·ETF·뉴스 근거.
- `integrated_readiness.json`: 가격 심사와 연결 근거, 사전 기록, 파일 해시를 합친 기계 판독 결과.
- `reports/private/context_ledger/<기록>/forecast.json`: 최초 사전 판단. 관찰이 끝난 뒤 별도 `outcome.json`을 만든다.

표준 출력에는 상태·건수·파일 위치만 표시한다. 가격과 파생값은 개인용 파일에 남긴다. 외부 LLM 호출과 토큰 사용은 0이며 실제 가격의 ML 학습은 수행하지 않는다. 정식 목표가·매력도 점수·예상 수익 실현 시기·검증 ID는 계속 비워 둔다.

다음 작업은 확인하지 못한 뉴스 주제와 사건의 실제 영향을 보완하고, 5거래일이 지난 뒤 저장한 예측과 실제 가격 결과를 비교하는 것이다. 실데이터 ML 학습권 확인과 충분한 실제 검증 표본 확보는 별도 미완료 과제로 유지한다.
