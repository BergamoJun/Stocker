# 평가 결과 해석 도구

2026-11-08 추가한 개인용 로컬 연구 모듈이다. 기존 예측과 실제 결과의 성적표·오답 분석을 만들며, 고점 예측 수식이나 진행 중인 수집 작업을 변경하지 않는다. 실제 ML 학습·추천 점수 승인·최종 시험은 별도 단계다.

```mermaid
flowchart LR
  A[가격 수집·검증] --> B[고정 수식의 예측]
  B --> C[실제 5거래일 결과와 대조]
  C --> D[기존 기준일별 평가 파일]
  D --> E[새 평가 결과 해석 도구]
  E --> F[불확실성·자료 부족·실패 원인 보고서]
  F --> G[별도 개선 후보 등록·재평가]
```

## 현재 집계에 추가한 것

| 기능 | 확인하는 질문 | 구현 |
|---|---|---|
| 동일 조건 비교 | 비용 후 단순 보유보다 나았는가? | 같은 기업·기준일·비용에서 짝지은 수익 차이와 체결 경계 |
| 기간 의존성 | 주식 수가 많아 보이는 만큼 확실한가? | 같은 날짜의 기업들을 함께 유지한 연속 기간 묶음 재표집 |
| 자료 부족 보존 | 계산할 수 없는 자료가 결과에서 사라졌는가? | 예정 기업×기준일 분모, 미해결 사유와 비교 가능한 비율 |
| 조건별 실패 분석 | 어떤 조건에서 오차·손실·거래 보류가 컸는가? | 산업/구간/월/변동폭/거래대금/기업별 집계 |
| 특정 시기 의존성 | 한 달이 전체 성적을 좌우하는가? | 모든 월에 대해 그 달을 하나씩 제외한 비교 성적. 새 수식 선택에는 사용하지 않음 |
| 읽기 쉬운 설명 | 다음에 무엇을 확인해야 하는가? | 자료 감사, 시간 범위 확대, 관망 결과, 비용 후 이익과 상대 성적의 차이 등을 정해진 한국어 문장으로 설명 |

기존 `historical_panel.py`·`panel_report.py`와 BE 관찰 코드는 그대로 둔다. 새 코드는 `panel_diagnostics.py`(입력/출력), `panel_statistics.py`(통계), `panel_diagnostic_report.py`(한국어 설명), `panel_diagnostics_demo.py`(가상 결과 예제)다.

## 입력과 잠금

실제 대규모 작업은 `--job <job.json>`으로 읽는다. 코드/정책/사용권/산업 정의의 원래 해시, 고정 표본 해시, 기업별 가격 입력·프로필·계산 엔진의 기록을 확인한다. 개인용 로컬 파생 분석 사용권 검사가 실제 결과 파일 파싱보다 먼저다. 키를 읽거나 새 API를 요청하지 않는다.

원본 작업이 `complete` 또는 `complete_with_gaps`의 `done` 단계가 되기 전에는 성적을 집계하지 않는다. 진행 상황을 설명하는 대기 보고서만 만든다. 먼저 끝난 기업의 성적만으로 전체를 판단하는 것을 막는다. 원본 작업이 확인 불가/한도 도달이면 미완료 상태를 그대로 표시한다.

고정 표본의 개발·중간 확인용 기업과 두 구간만 읽는다. 마지막 시험 전용 기업 폴더는 열지 않는다. 기준일 파일 이름이 예정 목록 밖에 있으면 내용은 읽지 않고 보류한다. 중복 기업·중복 사례·알 수 없는 구간·다른 5일 결과 창·예정 분모 누락·실제/가상 혼합은 거절한다.

가격 입력이 확인되지 않은 기업도 예정 분모에서 없애지 않는다. 기업별 계산 불가, 기준일 가격 부족, 이후 5일 부족, 계산 지원 범위 밖, 결과 파일 누락을 구분한다. 이 상태는 손익 미해결이며 현금 수익 0%를 넣지 않는다. 계산 결과가 거래 보류인 경우의 0%는 그대로 유지한다.

## 비교 성적과 체결 경계

`비교 성적(%p) = 모델의 비용 후 가상 수익률(%) − 같은 기간 단순 보유의 비용 후 수익률(%)`

평균은 비교 가능한 사례를 동일 비중으로 계산한다. 자료가 없는 사례는 평균에 값을 넣지 않고 전체 예정 수와 누락 비율에 남긴다. 따라서 구간은 고정한 기업 집단과 관측 가능했던 비교 사례에 조건부다. 누락 선택의 편향까지 해결한 추정으로 해석하지 않는다.

하루에 목표·손실 기준이 모두 닿아 순서를 모르면 수익의 하한·상한을 유지한다. 두 경계의 평균과 재표집 구간도 각각 계산한다. 둘 중 유리한 체결만 고르지 않는다. 거래 비용은 기존 편도 10/25bp 가정을 사용한다. 10bp는 매수·매도 각각 0.10%, 25bp는 각각 0.25%다.

고점 가격 오차는 최근 14거래일의 평균적인 하루 가격 변동 폭(ATR) 단위로, 고점 날짜 오차는 거래일 단위로 표시한다. 목표에 먼저 도달한 경로에서의 기간 비교는 별도 조건부 통계다. 고점 구간 적중률이나 목표 우선 도달 비율을 전체 매매 승률로 바꾸지 않는다.

## 연속 기간 묶음의 재표집

설정은 `config/panel_diagnostics_policy.json`의 별도 버전으로 기록했다. 대규모 산업별 성적을 읽기 전에 정했으며, 이후 바꾸는 설정은 다른 후보 버전과 실행 기록으로 남겨야 한다.

1. 산업군·구간별로 같은 기준일의 모든 기업 결과를 한 날짜 묶음으로 만든다. 개발/중간 구간은 합치지 않는다.
2. 연속된 기준일 4개를 기본 묶음으로 쓴다. 기준일 간격이 5거래일이므로 약 20거래일이다. 2개·8개 묶음도 사전에 지정한 민감도 확인용으로 모두 보존한다.
3. 해당 구간 안에서 가능한 연속 묶음을 중복 허용 추출해 원래 날짜 수만큼 이어 붙인다. 끝에서 시작으로 감는 순환은 하지 않는다. 서로 다른 구간의 경계도 넘지 않는다.
4. 한 번 선택한 날짜 인덱스는 그날 모든 기업, 모델·비교 대상, 두 비용 가정에 함께 적용한다. 같은 구간의 산업군들도 동일한 달력 추출을 쓴다.
5. 2,000회 반복하고 각 통계의 2.5/97.5 백분위를 구한다. 실행 경계 하단 구간의 하단과 상단 구간의 상단을 보수적 외곽 범위로 표시한다.

이 방법은 연속 관측의 블록 재표집을 사용한다. [Künsch의 원 연구](https://doi.org/10.1214/aos/1176347265). 랜덤 길이의 순환 묶음을 쓰는 stationary bootstrap과는 구현이 다르다. [관련 Politis–Romano 연구](https://doi.org/10.1080/01621459.1994.10476870).

통계적 전제는 묶음 길이가 관련 단기 의존성을 충분히 포착하고 구간 안의 시장 특성이 추정에 적절할 만큼 안정적이라는 것이다. 시장 국면 변화·긴 의존성이 있으면 참고 구간의 해석도 제한된다. 비순환 묶음은 가장자리 관측의 추출 가중치가 중앙과 다를 수 있다. 세 묶음 길이를 비교해도 모든 편향이 없어지는 것은 아니다.

추출 난수는 정책 시드·구간·날짜 목록·묶음 길이에서 결정한다. 입력 순서를 바꾸어도 성적이 달라지지 않도록 정렬한다. 원래 금액·수익 평균은 Decimal로, 재표집 통계는 float64로 계산한다. 예측의 가격·목표·손익 원본은 바꾸지 않는다.

## 구간 계산의 최소 조건

- 산업군별 선정 기업 100개 이상. 이 중 마지막 시험 전용 기업은 계속 보관한다.
- 해당 구간에서 비교 가능한 서로 다른 기업 60개 이상.
- 서로 다른 기준일 16개 이상과 명목상 겹치지 않는 기간 묶음 8개 이상.
- 전체 예정 기업×기준일의 90% 이상이 비교 가능하고, 비교 자료가 전혀 없는 기준일이 없어야 한다.
- BE 한 종목의 실행 점검은 기업 수에 관계없이 일반화 추정을 보류한다.

이 조건은 이번 연구의 사전 최소 확인 기준이며 통계적 보정·대표성·충분한 표본을 보장하지 않는다. 명목 묶음 수를 추정한 독립 표본 수로 표시하지 않으며 `independent_sample_count`는 비워 둔다.

기존 전체 이력 계획에서 개발은 50개·중간 확인은 16개 기준일이다. 중간 확인 16개는 기본 4개 묶음으로 명목 4묶음이므로 기본 구간을 보류한다. 더 짧은 2개 묶음에서 계산이 돼도 기본 결론을 그 결과로 바꾸지 않는다. 개발 50개도 8개 묶음의 최소 8묶음은 충족하지 못한다. 따라서 많은 기업을 모았다는 이유만으로 시간 범위의 부족까지 해결했다고 판단하지 않는다.

월을 하나씩 제외한 분석은 특정 시기에 의존하는지 확인하는 설명용 검사다. 공식 유의성 검사·추가 학습·최적 기간 선택이 아니다. 여러 산업·비용·묶음의 구간도 다중 비교를 보정한 발견으로 제시하지 않는다. 0을 포함하는 구간은 우위의 근거가 불확실하다는 뜻이며 효과가 없거나 동일하다는 증명이 아니다.

## 실행과 결과 파일

Stocker 가상환경에서 실행한다. 새 패키지·API 키·외부 AI 호출이 필요하지 않다.

```powershell
# 현재 전체 작업 확인: 완료 전에는 성적 없이 대기 보고서 저장
.\.venv\Scripts\python.exe -B -m research.panel_diagnostics --job reports/private/historical_panel/58488d99d05b4d1e/job.json

# 기존 BE 66개 기준일의 읽기·집계·설명 확인
.\.venv\Scripts\python.exe -B -m research.panel_diagnostics --pilot reports/private/historical_panel_pilot/20261107T165029073340Z

# 실제 시장 자료가 아닌 가상 사례로 기간 묶음 계산까지 확인
.\.venv\Scripts\python.exe -B -m research.panel_diagnostics --demo
```

명령은 한 번 실행한 시점의 결과를 저장한다. 현재 백그라운드 작업을 수정하거나 새 예약 작업을 설치하지 않는다. 대규모 수집·평가 완료 후 첫 명령을 다시 실행하면 전체 해석을 생성한다.

저장 위치는 `reports/private/panel_diagnostics/real/<UTC시각>/` 또는 `illustrative/<UTC시각>/`다. 이전 결과는 덮어쓰지 않는다.

- `REPORT.ko.md`: 무엇을 평가했는지, 비교 성적과 단위, 범위/표본 부족, 다음 확인 순서.
- `diagnostics.json`: 구간·산업군별 통계, 두 비용과 모든 묶음 길이, 월/변동폭/거래대금/기업별 내역, 월 제외 민감도.
- `inputs.json`: 사용한 파일과 해시, 정책 원본, 해석 코드/계약 해시, 입력 지문. 원본의 실제 평가·관측 시각은 보존된 평가 파일에서 추적한다.
- 가상 실행만 `illustrative_input.json`을 추가 저장한다. 실제/가상 공간과 표기를 분리한다.

표준 출력에는 상태·건수·결과 경로만 내보낸다. 개인 가격·파생 수익 수치를 외부 LLM으로 보내지 않는다. 이 도구가 쓰는 네트워크 요청·LLM 호출·학습은 0회이며 기존 자료의 현재 개인용 분석 권리는 검사한다.

## 결과를 사용하는 범위

자료 누락, 모든 판단의 현금 관망, 비용 후 비양의 성적, 목표 도달기간 표본 부족, 특정 월 의존성, 시간 범위 부족을 설명한다. 그 설명으로 새 후보를 설계할 수 있지만 원래 수식을 자동 변경하지 않는다. 새로운 실제 표본이 생기거나 마지막 시험을 통과한 것으로 표현하지 않는다.

계좌 자금 배분·누적 수익률·배당·현금 이자·시장 충격은 계산 대상이 아니다. 현재에 받은 약 2년의 정정·분할 조정 자료와 SIC 조회의 역사적 원본 미인증도 남는다. 성적 해석만으로 추천 점수·상승 확률·수익성 승인은 활성화되지 않는다.

검사는 `tests/test_panel_diagnostics.py`에 있다. 완전 동조 종목 복제가 구간을 축소하지 않음, 모델/보유의 동일 날짜 비교, 체결 경계, 누락/관망 구분, 기간 부족, 월 의존성, 순서 불변성, 원본/최종 시험/사용권/출력 계약을 확인한다. 합성 검사와 BE 읽기 확인은 여러 산업의 실제 예측력 검증과 구분한다.
