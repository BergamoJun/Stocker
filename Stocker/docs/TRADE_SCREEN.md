## 예측과 수치 후보의 분리

기존 고점 예측은 가격·시기 경로를 계산한다. 새 `research.trade_screen`은 그 예측과 기준일까지의 근거만 받아 수치 검토 후보/보류/입력 불가를 구분한다. 실현된 미래 가격·수익·정답은 필터 입력으로 사용하지 않는다. 최고가를 예상해도 비용 후 수익 기회가 부족하면 보류할 수 있다.

정책은 `config/trade_screen_policy.json`의 `five-session-cost-risk-screen-v1`이다. 기존 고정 통계·Ridge·ATR 동결 정책은 변경하지 않는다. 기준 종가 P, 목표 T, 무효화 I, 편도 비용 c(bp), f=c/10000일 때:

- 목표 비용 후 수익률 U = 100×[T×(1−f)/(P×(1+f))−1]
- 무효화 비용 후 수익률 D = 100×[I×(1−f)/(P×(1+f))−1]
- 비용 후 손익비 = U/(−D)

기준 비용 25bp에서 U>0, 비용 후 손익비≥1, 모델의 경로별 추정 평균 수익 경계 중 하단>0을 모두 요구한다. 과도한 보류 여부를 숨기지 않는다. 10bp 결과도 보존하지만 심사 기준을 비용에 따라 결과에 맞춰 바꾸지 않는다.

이 기준은 이전 비용 진단을 근거로 정한 구조적 양의 수익·대칭 손익비 조건이며, 수익을 최대화하도록 학습한 최적 임계값이 아니다. 새 평가 결과를 보고 임계값을 바꾸지 않는다. 추정 평균 수익의 하단은 같은 일봉 목표/무효화 선후를 보수적으로 처리한 값으로, **통계적 신뢰 하한이나 실제 미래 손익 보장값이 아니다.**

유효 관측 지원≥30과 목표 우선 도달기간 추정도 필요하다. 고정 통계 모형의 512개 시뮬레이션을 관측 512개로 세지 않고 EWMA 유효 관측 수를 사용한다. 학습 모형은 별도 오차 추정 경로의 유효 표본 수를 사용한다. 신뢰도·매력도·보정된 승률을 이 숫자에서 만들지 않는다.

유효한 양의 매매 계획 없음, 비용 후 여력/손익비/평균 수익 부족, 표본 부족, 목표 기간 추정 없음은 보류다. 모형/비용 입력 결손·비유한 값·참조 불일치는 입력 불가다. 실시간이 아닌 기준 종가를 가정한 연구 필터이며, 다음 시가의 갭과 실제 체결 가능 여부는 별도 확인해야 한다.

현재 연구 모드는 가격의 현재성·기한을 검사하고, 과거 진단은 명시적인 `historical_diagnostic` 모드로 구분한다. 현재성 검사를 우회해 오래된 가격을 현재 계획으로 사용하지 않는다.

## 새 독립 시드 검증

`config/trade_screen_evaluation.json`에 결과 확인 전 새 시드 24개와 기존 5시장·고정 경계를 기록했다. 기존 표본 검토와 겹치지 않는 시드이며 총 120개 데이터셋이다. 학습 123개·오차 추정 40개·평가 86개를 유지한다. 기본 거래량 포함 ML 예측을 필터 전후 비교하며 기존 통계 엔진을 교체하지 않는다.

비교 모집단은 모든 예측/필터 계산 가능 기준일이다. 거절한 기준일의 현금 0을 분모에 유지해 선택한 거래만의 수익을 전체 성능처럼 표시하지 않는다. 예측 불가와 필터 입력 불가는 별도로 세며 현금으로 대체하지 않는다. 다음 시가가 계획 밖이면 미진입, 같은 일봉에서 양방향 도달하면 무효화~목표의 비용 후 손익 경계를 유지한다.

필터가 통과시킨 사례는 전후 실행이 같으므로 짝 차이는 0이다. 모호 체결 사례를 양쪽의 독립적인 경계로 빼 불확실성을 잘못 부풀리지 않는다. 거절한 사례의 전후 손익 차이는 원래 수익 경계의 부호를 뒤집은 값이다. 전체 기준일 평균과 실제 진입 수를 함께 저장한다. 모두 거절해서 0인 경우는 수익성 증거가 아니라 미진입이다.

시드별 평균 차이와 명목 99.8% 근사 t 구간을 보존한다. 유한분산·시드 평균 근사 정규성 가정이 있으며 실제 시장의 수익 확률을 뜻하지 않는다. 새 합성 시드의 결과도 실제 BE 성능 검증을 대체하지 않는다. 기존에 본 결과를 재사용하는 경우에는 개발 진단으로만 구분한다.

```powershell
./.venv/Scripts/python.exe -B -m research.trade_evaluation
```

결과·모델·입력 해시·코드 원본·원래/필터 후 체결 결과는 ignored `reports/private/trade_evaluation/<시각>/`에 저장한다. 실제 가격 파일 인자를 받지 않는다. LLM 호출·토큰·데이터 구매는 0이다.

## 실제 BE 준비 상태 CLI

```powershell
./.venv/Scripts/python.exe -B -m research.trade_readiness
```

개인용 권한을 확인한 저장 BE 가격의 원본/정규화 해시와 최신 완료 세션을 검사하고, **고정 통계 모형**으로 새 후보를 계산해 같은 필터를 적용한다. 실제 ML 학습은 수행하지 않는다. 네트워크나 API 키도 필요 없다. 값은 ignored `reports/private/trade_readiness/<시각>/trade_readiness.json/.md`에만 보존하고 CLI stdout에는 상태·사유·경로만 출력한다.

이 연결 과정에서 기본 스냅샷 선택이 `diagnostic-...` 폴더를 최신 숫자 시각 폴더보다 우선하던 문제를 수정했다. 이제 내부 캡처의 UTC 시각 폴더만 기본 선택 대상으로 삼는다. 권한 검사 전 가격을 읽는 선택 방식으로 되돌리지 않는다. 현재 가격 검사는 계속 엄격하게 유지한다.

현재 CLI의 추천 보고서 목표·점수·기간·검증 ID는 null이다. 현재 뉴스/시장/재무 특징 결합, 실제 예측 성능 검증과 ML 학습 권한은 별도 준비 항목으로 표시한다. 숫자 필터 통과를 전체 추천도 통과로 해석하지 않는다.

계약은 `schemas/trade_screen.schema.json`, `schemas/trade_evaluation.schema.json`이다. 입력 결손·비용·모호 체결·미래 정답 비사용·현재성·원본 선택 회귀를 `tests/test_trade_screen.py`에서 검사한다.
