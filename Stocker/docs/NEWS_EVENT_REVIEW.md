# 뉴스가 BE 판단에 어떤 근거를 더하는지 평가하는 절차

이 단계는 “뉴스를 찾았다”와 “그 사건이 BE에 어떤 영향을 주는지 검토했다”를 구분한다. 제목이나 최신 날짜만으로 호재 점수를 주지 않는다. 원문과 관련성을 확인한 뒤 좋은 영향은 가산하고 나쁜 영향은 감점하는 기존 연구용 수식을 연결한다. 최종 투자 매력도 1~100점이나 검증된 주가 상승 확률을 제공하는 단계는 아니다.

## 무엇을 평가하는가

| 평가 항목 | 확인할 질문 | 부족하면 어떻게 하는가 |
|---|---|---|
| 뉴스 검색 범위 | 기업·업종·거시경제/정치·원자재 네 주제의 제한된 검색을 실제로 수행했는가? | 확인하지 못한 주제를 표시하고 뉴스 전체 점수를 보류한다. |
| 원문 공개 시각 | 공급자나 검색기의 시각 대신 실제 원문 발행 시각을 확인했는가? | 링크만 표시하고 사건 점수를 계산하지 않는다. |
| 사업 및 기간 관련성 | BE의 매출·비용·자금 조달·수요나 약 5거래일 가격에 영향을 줄 구체적 이유가 있는가? | 관련성 검토를 대기 상태로 남긴다. |
| 영향의 방향과 크기 | 좋은 영향·나쁜 영향·영향 없음/혼재 중 어떤 판단이며, 근거는 무엇인가? | 임의의 긍정 판단을 넣지 않는다. |
| 새로운 사실 여부 | 새 사건인가, 새 사실이 추가된 사건인가, 오래된 사건의 재보도인가? | 발행일이 최근이라는 이유만으로 오래된 사건을 새 사건으로 바꾸지 않는다. |
| 반론과 후속 관찰 | 반대 해석과 앞으로 확인할 발표·사업 사건은 무엇인가? | 검토가 완료된 사건으로 접수하지 않는다. |

원문을 읽은 검토자가 이 내용을 기록한다. 프로그램은 출처·날짜·항목의 일관성을 검사하며, 입력한 해석이 사실인지 자동으로 보증하지 않는다. 별도의 학습형 뉴스 AI나 기사 본문 수집·외부 LLM 전달을 추가하지 않았다.

## 뉴스 장애를 보완하는 무료 공식 자료

GDELT 요청 제한이 계속될 때 사용할 보완 자료로 두 공식 피드를 추가했다. 기존 회사 뉴스 보완 경로인 Massive 메타데이터도 유지한다. 추가 가입·결제·API 키는 필요하지 않다.

| 공식 피드 | 보완하는 내용 | 범위의 한계 |
|---|---|---|
| 미국 연방준비제도 통화정책 발표 | 미국 통화정책의 공식 발표 날짜와 원문 | 세계 경제·정치 전체나 모든 중앙은행을 다루지 않는다. |
| 미국 에너지정보청(EIA) Today in Energy | 에너지 환경에 관한 공식 발표 날짜와 원문 | 연료전지 전용 정보가 아니며 모든 원자재·국제 분쟁을 다루지 않는다. |

[연준 이용 정책](https://www.federalreserve.gov/disclaimer.htm)은 별도 표시가 없는 정보의 재사용을 허용하며 출처 표시를 요청한다. [EIA 재사용 정책](https://www.eia.gov/about/copyrights_reuse.php)도 출처·발행일 표시를 요청하며 제3자 자료의 예외를 둔다. 이번 연결은 공식 기관의 제목·날짜·원문 링크만 저장하며 본문·요약·차트·이미지·제3자 수치 데이터는 보관하지 않는다. 사용 범위와 재검토일은 `official_news_entitlements.json`에 기록했다. FRED API와는 별개이며 기존 FRED 차단은 유지한다.

최근 7일 안의 항목을 최대 25건씩 확인한다. 피드의 표기 날짜는 아직 원문의 독립 검증 결과가 아니므로 `published_at`으로 옮기지 않는다. 공식 피드가 조회됐더라도 일반 뉴스 검색의 네 주제가 모두 확인됐다고 처리하지 않는다. 오래된 항목만 있으면 ‘이번 기간에 해당 피드에서 찾은 항목 없음’으로 표시하며, 정책 위험이 없다는 뜻으로 쓰지 않는다.

한 번의 실행은 피드당 최대 한 번 요청한다. 두 요청 간격은 15초이고, 같은 피드는 15분 동안 저장 결과를 사용한다. 캐시를 읽어도 최초 관측 시각을 새 시각으로 바꾸지 않는다. 실패한 요청도 저장해 즉시 반복하지 않는다. 기사에 쓴 표현을 바꾸지 않도록 XML에 선언된 UTF-8·ISO-8859-1 인코딩을 엄격하게 해석하며, 잘못된 문자로 대체하지 않는다. 피드 본문 크기는 1MB로 제한하고 DTD·엔티티 선언과 외부 호스트의 기사 링크를 거부한다.

## 어떤 계산식을 쓰는가

기존 `swing-news-candidate-v1`의 수식과 파라미터를 바꾸지 않았다. 사건 하나의 방향은 좋은 영향 +1, 나쁜 영향 -1, 검토 결과 영향 없음 0이다. 혼재한 사건을 자동으로 긍정 처리하지 않는다.

`사건의 기여도 = 방향 × 영향 크기 × BE 관련성 × 근거 신뢰도 × 최신성 × 새 사실 여부`

- 영향 크기: 작음 0.25, 중간 0.5, 큼 1.
- 관련성: 회사 직접 관련 1, 업종 관련 0.75, 거시경제 관련 0.5.
- 근거 신뢰도: 일차 자료 1, 독립 확인 0.8, 단일 신뢰 매체 0.6, 미확인 0.
- 최신성: 최초로 알려진 사건 시각부터 24시간마다 절반으로 줄인다. 7일을 넘으면 0이다. 실제 새 사실을 확인한 업데이트만 그 업데이트 시각을 사용할 수 있다.
- 새 사실 여부: 새 사건·검토한 중요 업데이트는 1, 재보도는 0.

같은 사건은 중복 계산하지 않는다. 강한 영향의 사건을 최대 5개 사용하고, 합계가 -1~+1을 벗어나면 그 범위로 제한한다. **자료와 검토가 모두 갖춰진 경우에만** `20 + 20 × 사건 기여도 합계`로 연구용 뉴스 부분 점수 0~40을 만든다. 이 값은 전체 투자 매력도와 상승 확률이 아니다.

여기서 20은 검토가 끝난 경우에 사용하는 수식의 기준점이다. 자료를 찾지 못했거나 검토하지 않은 경우에 대신 넣는 중립값이 아니다. 그런 경우 점수는 비워 둔다. 다른 항목의 비중을 늘려 빈 뉴스 40점을 메우지도 않는다.

## 원문 검토 입력과 기록 보존

보고서를 만들면 `news_review_queue.json`에 기사별 확인 질문을 남기고 `review_input.template.json`을 만든다. 양식은 `template_only: true`, 빈 검토자와 빈 사건 목록으로 시작한다. 이 상태에서는 점수를 계산하지 않는다.

완료한 검토는 별도 파일로 저장한다. `news_event_review.schema.json`은 다음 정보를 요구한다.

- 검토자, 검토 제출 시각, 검토 대상 메타데이터의 해시. 해시는 파일 내용이 같은지 확인하는 식별값이다.
- 사건 ID와 원문 링크·출처 ID, 원문을 확인한 시각, 검증한 발행 시각.
- 영향의 근거, 약 5거래일과 관련되는 이유, 반론, 앞으로 확인할 사건.
- 좋은/나쁜 영향, 영향 크기·관련성·신뢰도·새 사실 여부. 실제 검토와 관계없다고 판정한 기사도 그 이유를 남긴다.

검토는 기사를 실제 관측한 뒤 수행해야 한다. 미래 시각이나 다른 메타데이터에 묶인 검토, 초안, 빠진 원문 확인, 같은 사건에 대한 상반된 방향은 점수를 보류한다. 새 기사가 추가됐거나 원문 메타데이터가 바뀌면 기존 검토를 새 입력에 조용히 재사용하지 않는다. 현재는 변경된 입력을 다시 검토하는 보수적인 방식을 사용한다.

이미 저장한 가격·비용 사전 판단은 이 단계에서 바꾸지 않는다. 새 뉴스와 검토는 새 보고서에 남긴다. 최초 사전 기록이 참조하는 근거 파일과 정책 해시는 보존한다. 아직 5거래일이 지나지 않은 실제 예측은 성공·실패로 판정하지 않는다.

## 실행 방법

Stocker 가상환경에서 다음 순서로 실행한다. 새 공식 자료 조회만 네트워크를 사용한다.

```bash
python -m research.official_news
python -m research.context_report
python -m research.event_review
```

마지막 명령은 가장 최근 `evidence_context.json`에 대한 대기 목록·빈 입력 양식·보류 사유를 `reports/private/news_review/`에 저장한다. 원문 검토를 별도 파일에 완료했다면 다음처럼 동일한 근거 파일과 함께 검사한다.

```bash
python -m research.event_review --context reports/private/context_report/<시각>/evidence_context.json --reviews <검토파일.json>
```

저장 자료를 합쳐 보고서에 반영하려면 `research.context_report --event-reviews <검토파일.json>`을 사용한다. 새 기사·자료 만료로 메타데이터 해시가 달라지면 해당 검토를 적용하지 않는다. 검토자는 원문을 읽고 판단을 채워야 하며, 프로그램이 제공한 빈 양식을 승인 기록으로 바꾸지 않는다. 개인 가격과 공급자 뉴스 원문을 외부 LLM에 보내는 경로는 계속 꺼져 있다.

입력 구조는 `examples/illustrative_news_context.json`과 `examples/illustrative_news_reviews.json`에 가상 예제로 제공한다. 가상 예제는 실제 뉴스가 아니며 고정된 과거 시각의 테스트 입력이다. CLI 결과에는 실제/가상 분류와 원본·검토 파일·정책·스키마·계산 코드의 해시를 함께 저장한다. 과거 연결 보고서에 분류가 없다면 새 `context_report`를 생성한 뒤 검토 경로를 사용한다.

## 테스트 결과를 읽는 방법

검토를 지속 보관하고 기사 버전/예측 시각에 연결하는 후속 모듈은 [NEWS_CONNECTIONS.md](NEWS_CONNECTIONS.md)에 있다. 기존 전체 뉴스 묶음 검증은 그대로 유지하고, 설명용 버전별 재사용과 숫자 점수 승인을 구분한다. 구버전 원본 예측은 변경하지 않는다.

`tests/test_news_review.py`는 가상 기사·가상 검토 입력으로 동작을 검사한다. 최근의 같은 강도 호재와 악재가 기준점에서 각각 위·아래로 같은 크기만큼 반영되는지, 오래된 사건·재보도·중복이 최신성 보너스를 얻지 않는지, 미검토 기사·미확인 주제·잘못된 날짜가 점수로 바뀌지 않는지를 본다.

이 테스트가 통과했다는 것은 정한 계산 규칙을 프로그램이 지켰다는 뜻이다. 실제 BE 뉴스가 미래 주가나 수익률을 더 잘 예측하게 만들었다는 뜻은 아니다. 실제 검증에는 미리 저장한 뉴스·해석과 이후 가격을 반복해서 비교한 기록이 필요하다. 첫 11월 9~13일 관찰의 결과는 가장 빨라도 11월 14일 14:02 KST 이후 조회한다. 한 건만으로도 예측력을 승인하지 않는다.
