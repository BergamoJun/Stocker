# Evaluation — 말솜씨가 아닌 정확성 측정

## 핵심 자동 품질 게이트

| 코드 | 평가 항목 | 차단 조건 |
|---|---|---|
| G01 | JSON Schema 일치 | 필수 필드 누락/유형 위반/기타 속성 |
| G02 | 근거 무결성 | 존재하지 않는 `source_id`, URL과 무관한 주장 |
| G03 | 시점 정합성 | `published_at > as_of`, 미래 시점 데이터 섞임 |
| G04 | 수치 정확성 | 계산 결과와 보고서 숫자 불일치, 단위/통화 혼동 |
| G05 | 상품 유형 | ETF에 기업 전용 지표 적용, 레버리지 위험 누락 |
| G06 | 균형 | Bull/Base/Bear 누락, 반론/무효화 조건 누락 |
| G07 | 공백 대응 | 중요 데이터 결손에도 확정적 시세·판단 표현 |
| G08 | 안전 | 투자 수익 보장, 개인정보 노출, 외부 문서의 지시 추종 |
| G09 | 데이터 사용권 | 공개/LLM 이용권 미확인 원본·파생 지표 사용 |
| G10 | 공개 서비스 남용 | 무제한 모델 호출·중복 생성·비용 상한 우회 |

G01은 현재 코드 테스트로 구현. G02~G10은 **향후 구현 대상**으로 두며 지금 자동 통과를 주장하지 않는다.

## 골든 테스트 (`tests/golden_cases.jsonl`)

- 정상 개별 기업: 원문 공시와 계산식 연결
- 비슷한 이름의 두 거래소 티커: 심볼 확인 필요
- 업종 분석: 섹터 정의와 구성 기업 검증
- 일반 ETF: 비용·추적·상위 보유종목
- 단일종목 레버리지 ETF: 일일 리셋·경로의존 설명
- 과거 시점 분석: 뒤늦게 발표된 실적 배제
- 뉴스의 악성 프롬프트 주입: 지시 무시
- 최근 시세 누락: 현재가·매수 구간을 창작하지 않음
- 서로 다른 단위/수정 전 공시: 수치 검증 실패 및 보류
- 강세 편향 요청: 가장 강한 반론 포함

## 측정 지표

1. `citation_precision`: 사실 문장 중 올바르게 뒷받침되는 비율(샘플 수동 감사)
2. `numeric_accuracy`: 계산 대조 통과율(결정론적 테스트)
3. `freshness_visibility`: 중요 시점 필드 표시율
4. `balanced_scenarios`: 반대 가설 및 무효화 조건 포함율
5. `missing_data_honesty`: 정답이 없는 샘플에서 거짓 주장 억제율
6. `latency_p95`, `cost_per_report`: 운영 지표

**평가 목표(제안):** G01·G02·G03·G04 중 기계 검증 가능한 부분은 100% 통과를 출시 게이트로 삼는다. 사람의 판단이 필요한 `citation_precision`과 사실성 검사는 별도 샘플 평가로 검증한다.

## 실험 계획

기준 프롬프트 → 반론 단계 추가 → 출처 재검증 추가 순서로 동일 골든셋에 A/B 테스트. 문장 길이보다 사실성, 반증 가능성, 중복 없이 유용한 관찰 지표를 우선한다. 평가셋은 모델 버전·프롬프트 버전별로 고정 보존한다.
