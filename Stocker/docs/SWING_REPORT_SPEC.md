# 스윙 리포트 명세 v0.3

> 2026-11-07 제품 방향 반영. 기존 기업·섹터 리서치를 근거로 유지하며 약 1주일 스윙매매 참고 요소를 먼저 보여준다.
> 현재 사용 범위는 개인용 로컬 CLI다. 개인 입력에는 수집·저장·로컬 계산 권리를 적용한다. 아래 공개/LLM 권리 조건은 해당 사용을 활성화할 때만 적용하며 현재 두 기능은 OFF다.
> 고점 구간·고점 형성일·목표 최초 도달일·수익 기회 점수의 새 연구 후보는 PEAK_MODEL.md를 따른다. 기존 보고서 계약 0.2.0의 검증/보류 조건은 유지한다.
> 현재 JSON 출력 계약 0.2.0, SEC 선택 행 CLI, 스윙/기간/매력도 후보 계산·시장 캘린더·뉴스 메타데이터 수집을 구현했다. 공개 가격 권리와 실제 이력 검증은 미완료여서 추천 보고서 수치로 활성화하지 않았다. 최신 상태는 MARKET_PREPARATION.md를 따른다.

## 1. 기간과 화면

- 기본 horizon은 `swing`이다. 기준가격이 속한 세션 다음 5개 정규장 세션을 관찰하며 기준 세션은 세지 않는다. 거래소 휴장·단축장을 캘린더로 처리한다.
- 기존 `short`(1~3개월), `medium`(3~12개월), `long`(1년 이상)은 의미를 유지하며 스윙 블록은 `not_requested`로 둔다.
- 상단: 한줄평 → 기준가격/1차 목표/상승여력 → 수익실현 검토 조건·시기 → 무효화 기준/하락폭/손익비 → 매력도와 가감점 근거.
- 하단: 기존 기업·섹터·상품 분석, bull/base/bear와 반론, 검증 지표, 출처, 데이터 공백.
- 매력도와 기존 `summary.evidence_confidence`는 별도로 표시한다. 어느 것도 상승/목표 도달 확률이 아니다.

## 2. 제공 상태와 가격 없는 리서치

최상위 `swing`는 항상 포함하며 `status`가 가격 시나리오의 준비 여부를 나타낸다.

| 상태 | 의미 | 가격 계획 | 매력도 |
|---|---|---|---|
| `not_requested` | horizon이 swing이 아님 | null | not_requested / score null |
| `unavailable` | 식별·가격 사용권·신선도·계산 방법/검증 중 하나라도 부족 | null, reasons 필수 | unavailable / score null |
| `available` | 가격 계획의 모든 선행 조건 충족 | 필수 provenance/방법론/시점 포함 | 검증된 점수 모델이 있으면 available, 없으면 unavailable / score null |

가격이 없더라도 SEC 기반 기업·사업 분석은 유지한다. 한줄평은 부족한 자료와 판단 보류를 설명할 수 있다. 목표가·무효화 가격·점수·도달 시기를 텍스트에 숨겨 제공 조건을 우회하지 않는다. 누락 항목은 `data_status.missing`과 `limitations`에도 표시한다.

매력도는 가격 계획과 독립적인 추가 게이트를 가지지만, 가격 계획이 불가하면 가격 기반 매력도도 불가하다. 모델이 없을 때 0점·50점·임의 점수로 대체하지 않는다.

## 3. 가격 입력과 조건부 1차 목표

초기 가격 계획은 **기준가격 대비 상방 시나리오**로 한정한다. 공매도, 개인별 평단·주문 수량·자동주문은 범위 밖이다.

- P = 기준가격, T = 조건부 1차 목표가격, I = 가설 무효화 가격.
- 같은 상품·통화·현재 주식수 기준에서 `T > P > I > 0`이어야 한다.
- 상승여력(%) = `(T / P - 1) * 100`.
- 하락폭(양수, %) = `(1 - I / P) * 100`.
- 손익비 = `(T - P) / (P - I)`. 유효한 분모가 없거나 기준을 역전하면 계획을 보류한다.
- 모두 기준가격 대비 **비용 전 가격 변동**이다. 기대수익률·실현 수익률이나 해당 가격의 체결 보장을 뜻하지 않는다. 수수료·스프레드·슬리피지·세금은 산식에 포함되지 않음을 표시한다.
- v0.3은 단일 1차 목표가격을 제공한다. 가격 구간·2차 목표는 후속 계약 변경으로 확장한다.

목표 T와 무효화 I의 선택 규칙 자체도 `methodology_id`로 등록하고 검증해야 한다. 계산 엔진이 제공한 값만 사용하며 LLM은 지지선·저항선·변동폭·상승률을 만들어내지 않는다. 산식 선택/입력 이력/반올림/가격 호가단위/검증 허용오차는 방법론 기록에 고정한다. 현재 ATR 후보 규칙과 계산은 연구용으로 구현했으나 실제 검증 전이므로 보고서 목표 산출은 비활성이다.

필수 입력/추적 항목:

- 종목 ID·이름·symbol·거래소·시간대, 통화, 가격 관측시각·세션 날짜.
- `eod | delayed` 구분. EOD는 delay_minutes null; delayed는 계약으로 확인한 1 이상의 지연 분 수를 기록.
- 기준가격은 실제 거래가격과 같은 `current_share_basis`. 과거 OHLCV의 분할/배당 조정 기준은 별도 보존하고 같은 주식수 기준으로 환산한다.
- `source_ids`, snapshot ID, 계산 ID들, 방법론 및 검증 기록 ID.
- 사용 범위별 권리 검토 ID. 개인용은 수집·저장·로컬 파생 분석을, 향후 공개/LLM 사용은 추가로 해당 권리를 확인한다. ID를 채웠다는 사실만으로 권리가 증명되지는 않는다.

종가를 실시간 '현재가'라고 표시하지 않는다. 최신 확보 종가 또는 지연 시세라고 명시한다. 가격이 오래되거나 조정/단위가 섞였으면 목표·무효화·손익비를 모두 보류한다.

## 4. 수익실현 검토와 시간

시간 항목을 구분한다.

| 항목 | 정의 |
|---|---|
| `holding_sessions=5` | 기준 세션 다음 5개 정규장 세션의 관찰기간. 개인의 실제 보유기간과 구분 |
| `review_at` | 관찰기간 마지막(5번째) 세션 종료시각; 목표 미도달/가설 지속 여부 재평가 |
| `expires_at` | 해당 가격 스냅샷으로 만든 보고서를 현재 참고자료로 표시할 수 있는 기한 |
| `take_profit_condition` | 목표 도달·촉매 변화 시 수익실현을 검토할 조건 |
| `time_review_condition` | 관찰기간 경과 또는 가설 변화 시 재평가할 조건 |
| `expected_target_sessions` | 검증 모델이 있는 경우에만 표시하는 1~5세션 범위의 조건부 도달 예상기간 |

- EOD 보고서의 기본 `expires_at`은 기준가격 다음 정규장 종료시각이다. 새 가격 스냅샷, 핵심 촉매 변경, 무효화 조건 발생은 더 이른 재평가 사유다. 지연 시세 TTL은 별도 공급자/방법론 검증 전 미지원이다.
- 보고서는 매 정규장 종료 후 갱신 대상으로 삼는다. 만료된 원문은 수정하지 않고 과거 자료 배지를 붙이며, 현재 유효한 시나리오로 재사용하지 않는다.
- 관찰기한과 보고서 만료는 다르다. 후속 리포트가 원 시나리오의 관찰기간을 소급 연장하지 않는다.
- 시각은 UTC ISO-8601로 저장하고 UI에는 거래소 시간대를 명시한다. calendar ID/버전으로 휴장일 계산을 재현한다.
- 도달기간 모델이 없으면 `expected_target_sessions`와 관련 방법론/검증 ID는 null이다. 고정 5거래일을 '5일 뒤 수익실현 예상'으로 바꾸지 않는다.

## 5. 매력도 1~100점

점수는 **기준가격과 스윙 기간에서의 시나리오 매력도**를 나타내는 정수다. 기업의 절대가치·승률·개인 적합성 점수가 아니다.

후보 평가 축은 가격/거래량, 기업 실적, 시장·섹터, 손익비, 최신 사건이다. **후보 정규화와 20/15/15/10/40 가중치는 정의했으나 실제 검증은 미완료**다. 신선도는 호재·악재의 영향 크기를 함께 높인다. 임의 점수로 보고서를 채우지 않으며 상세 후보/제약은 MARKET_PREPARATION.md를 따른다.

활성화 전 방법론 기록에 다음을 확정한다.

1. 대상 상품/모집단·기준시점·기간, 입력 필드/최소 이력·결손 처리.
2. 각 평가 축의 산식·가중치·정규화·1~100 매핑·반올림 규칙.
3. 동일 입력에서 같은 결과가 나오는 코드 버전과 입력 스냅샷.
4. 시점 보존 out-of-sample/walk-forward 평가 계획·실패 기준과 결과. 비용·슬리피지, 가격 조정, 데이터 누수, 생존자 편향, 점수 구간별 표본 수를 검토.
5. 등록 방법론 ID·검증 기록 ID 및 사용자에게 보여줄 가점/감점 근거와 source IDs.

가격 계획이 준비되어도 점수 모델이 검증되지 않았으면 `attractiveness.status=unavailable`, `score=null`이다. 테스트의 합성 모델 ID는 실서비스 검증 완료를 의미하지 않는다. evidence_confidence는 기존 근거 충분성·최신성·일관성 평가로 유지한다.

## 6. 섹터와 ETF

- 섹터 자체에는 거래가격을 만들지 않는다. 초기 스윙 가격 계획은 확인된 거래 가능 ETF proxy가 있을 때만 그 ETF의 가격으로 제시한다.
- proxy의 이름·symbol·ID·선택 근거·출처와 섹터 노출의 차이를 명시한다. 가격 quote의 종목 ID는 proxy ID와 같아야 한다.
- proxy는 검증된 allowlist에서 명시적으로 선택하며 대표 ETF를 임의로 지정하지 않는다. 지수는 방향 참고로 사용할 수 있으나 초기 거래 가격 계획의 대상은 아니다.
- ETF의 목표·무효화 가격은 ETF 자체 데이터로 계산한다. 레버리지/인버스 상품의 다일 가격을 기초자산 수익률의 단순 배수로 계산하지 않는다.
- proxy가 없으면 스윙 가격 계획·가격 기반 점수는 보류하고 섹터의 질적 분석은 유지한다.

## 7. 검증·계약 이행

스키마는 상태·타입·필수 메타데이터만 검사한다. 사실성·사용권·신선도·달력·산식·모델 검증 진위는 별도 서버 검증기가 필요하며 아직 구현되지 않았다.

실제 기능 활성화 전 최소 검증은: 출처 ID 존재/내용 일치, quote 및 촉매 공개시점 <= as_of, 통화/조정 정합성, T/P/I 정렬과 산식 재계산, 5세션 달력, 만료/재평가, 모델 등록/검증·결손 시 보류다. 일봉 하나에서 목표·무효화가 모두 충족되면 도달 순서를 추측하지 않고 평가를 불확정 또는 사전 정의한 보수적 규칙으로 처리한다.

새 JSON 계약은 `schema_version=0.2.0`이다. 0.1.0 예전 리포트를 새 계약으로 조용히 다시 표시하지 않는다. API 경로 /api/v1과 문서 스키마 버전은 별개다. 캐시/중복 키에는 계약·프로필·가격 snapshot·proxy·가격/점수/기간 방법론·검증 기록·캘린더 버전·사용권 상태를 포함한다.
