# PRD — Evidence-driven Equity Research (v0.2)

> 사용자 확정: **공개 무료 웹서비스, 미국 주식·ETF, EOD·지연 데이터 우선**. 가격·가격 파생 지표는 공개 및 AI 활용 권리 확인 전 비활성화. 상세 수용 기준은 MVP_SPEC.md에 있다.

## 1. 사용자와 문제

- 1차 사용자: 공개된 무료 웹에서 자신의 미국 주식/ETF 투자 아이디어를 검증하려는 일반 사용자.
- 해결할 문제: 뉴스 요약, 재무 지표, 산업 흐름, 리스크가 서로 다른 화면에 분리되어 있고 분석의 출처 및 반대 논리를 확인하기 어렵다.
- 핵심 약속: **검증 가능한 데이터와 명시적 가정으로부터 투자 논리·리스크를 조직화**한다.

## 2. MVP 범위

입력:

- 검색어: ticker/기업명/섹터명 (필수)
- 시장: US 전용 (MVP), KR은 향후 확장
- 분석 유형: `equity | sector | fund` (자동 분류 후 확인)
- 기간: `short | medium | long` (기본 `medium`; 분석 기간과 데이터 기간을 혼동하지 말 것)
- 옵션: 특별히 검증하고 싶은 가설, 투자 철학(가치·성장·퀄리티), 출력 깊이

출력:

- 식별된 투자 대상/상품 구조, 기준일·현재 데이터 상태
- 한 문단 요약, 근거 수준, 주요 투자 가설 및 반론
- 적절한 재무/시장/섹터 지표와 출처
- 강세·기준·약세 3개 시나리오, 핵심 전제·관찰 신호·무효화 조건
- 촉매, 리스크, 데이터 결손, 출처와 조회일
- 직전 리포트와 변경점(후속 기능)

## 3. 주요 기능 (우선순위)

| ID | 기능 | 우선순위 | 수용 기준 |
|---|---|---|---|
| F01 | 종목 식별/유형 분류 | P0 | 동명이인 티커/상장시장/ETF 유형 구분 실패 시 안전하게 중단 |
| F02 | 표준 데이터 수집 | P0 | 출처/수집 시각/회계기간/기준시각이 기록됨 |
| F03 | 재무·시장 계산 | P0 | 각 수치에 계산식·기간·입력 데이터 식별자가 있음 |
| F04 | 기업/ETF/섹터 전용 분석 | P0 | 잘못된 프레임워크 적용을 차단 |
| F05 | Bull/Base/Bear 시나리오 | P0 | 조건·반증 포인트 없이 가격 목표만 적으면 실패 |
| F06 | 출처 연결형 JSON 리포트 | P0 | JSON Schema 통과·근거 없는 사실 주장 차단 |
| F07 | 상반된 논리 검토 | P0 | 중요한 취약점/누락 항목이 사용자에게 노출 |
| F08 | 공개 웹 UI 및 저장 기록 | P0 | 익명 사용자가 생성된 리포트를 조회하고 원문 링크로 이동 |
| F09 | 개인 포트폴리오 위험 분석 | P2 | 별도 개인정보/법률 검토 후 추진 |
| F10 | 알림/정기 리포트/백테스트 | P2 | 데이터 라이선스·look-ahead 검증 후 추진 |

## 4. 비목표 / 경계

- 매매 주문, 자동매매, 수익 보장, 무근거 실시간 시세, 미확인 목표주가 제시.
- 초기 단계의 초단타/호가 기반 트레이딩 및 원인 없는 차트 패턴 단정.
- 컨센서스 유료 API/실시간 가격 feed가 없는데 이를 제공하는 듯한 표현.
- 공개 사용권을 확인하지 못한 EOD 가격의 표시·가공 또는 이를 사용한 PER/기술적 지표.

## 5. 품질 속성

- **정확성**: 사실 오류 0을 목표로 하되, 검증 불가/데이터 공백을 명시.
- **재현성**: 동일 데이터 스냅샷·설정·모델 버전으로 리포트 생성 과정을 재구성 가능.
- **관측 가능성**: 요청별 수집 성공/실패, 토큰/비용, 실행시간, 품질 게이트 통과율 기록.
- **보안**: 프롬프트 주입 격리, 키 비노출, 최소 수집, 사용자 데이터 별도 보호.
- **컴플라이언스**: 외부 공개/유료 서비스 전 법률 검토 필수.

## 6. 사용자 경험 예시

> 입력: `NVDA`, 미국, 중장기, "AI 데이터센터 CAPEX 둔화 가능성을 중심으로 반론까지 검토"

> 결과: 최신 확보 자료의 날짜·출처 + 실적/수요·마진·경쟁 분석 + 상반된 시나리오 + 감시 지표 + 불확실성.

결과는 생성 전에 데이터 신선도와 관련 위험을 확인한다. 리포트를 읽는 사용자가 **어떤 사실이 확인됐고 어떤 부분이 해석인지** 즉시 구분할 수 있어야 한다.
