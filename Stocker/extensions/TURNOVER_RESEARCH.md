# 거래대금 근사 후보와 자동 비교

종목의 약 5거래일 투자 기회를 판단할 때 평소보다 커진 거래 활동이 추가 정보를 주는지 검증한다. 큰 거래를 기관 순매수·미공개 정보·호재나 높은 승률로 인증하지 않는다. 기존 가격 모형·23변수 계수·비용 필터·추천도 보류와 이전 네 개의 예약 작업을 보존하는 별도 확장이다.

## 계산과 현재 보고서

`turnover_features.py`는 종가×보고된 거래량을 사용한다. 이것은 정확한 체결 거래대금이 아닌 근사 활동 지표다. Massive 공식 문서는 split 조정이 거래량에도 적용됨을 설명한다. 기존 어댑터의 split 조정 가격·거래량을 그대로 사용하며 소수 주식 수를 Decimal로 보존한다. VWAP(체결량 가중 평균 가격)을 새로 수집하거나 원래 자료를 덮어쓰지 않는다. [조정·소수 거래량](https://massive.com/knowledge-base/article/why-does-volume-return-as-a-decimal-value-from-the-aggregates-endpoint), [공식 일봉 계약](https://massive.com/docs/rest/stocks/aggregates/custom-bars).

- 상대 거래대금 근사 배수: 당일 `종가×거래량 / 직전 20일 종가×거래량의 중앙값`. 당일은 분모에서 제외한다.
- 날짜별 방향·활동 신호 B: `sign(종가-전일종가) × clip(상대배수-1,0,1)`. 하락에 동반된 확대는 음수다. 당일 신호를 -1~1로 제한해 한 번의 폭증이 무한 가점이 되지 않게 한다.
- 지속성 신호 C: `(B + 최근 3일 B 평균 + 최근 5일 B 평균) / 3`. 각 날짜의 B는 그 날짜 이전 20일 자료로 별도 계산한다. 세 항목은 서로 겹친 정보이며 독립 근거 세 개로 세지 않는다.
- 보조 자료: 종가의 일중 범위 위치, 최근 5일 가격 변화, 20일 평균과의 ATR 거리, 같은 기간 시장·업종 초과 변화. 보조 자료는 이번 후보의 추가 계수로 중복 합산하지 않는다.

숫자 20·3·5, clip 범위와 결합 비중은 사전 고정한 실험 설정이며 최적값으로 검증한 값이 아니다. 최소 25개 연속 세션을 요구한다. 비교 기준이 0이거나 필요한 자료가 없으면 값을 보류하며 대체값·가중치 재분배를 쓰지 않는다. 가격·거래량의 단위가 일관되게 split 재표현될 때 근사 곱은 보존된다. 현재 조정 자료가 당시 원본 상태임을 보증하지는 않는다.

`turnover_report.py`는 검증된 공통 입력을 읽어 BE/MSFT/XOM의 별도 한국어 연구 보고서를 만든다. 출처·자료 기준시각·방법·입력·출력 해시를 보존하고 계산과 문장을 재생한다. 현재 보고서는 가격의 완료 거래일·최초 실제 이용 가능 시각을 검사한다. 실험 변수 값은 로컬에만 저장하고 CLI에는 상태·종목·경로만 출력한다.

```powershell
.\.venv\Scripts\python.exe -B -m extensions.turnover_report --ticker BE --baseline <새 runtime.json>
.\.venv\Scripts\python.exe -B -m extensions.turnover_report --validate <출력 폴더>
```

## 같은 계수에서 비교

과거 비교는 원래 가격 9개 변수의 가중 합에서 거래량 변수의 계수 2만 교체한다. A는 원래 거래량, B는 상대 거래대금 근사, C는 지속성 결합이다. 나머지 변수와 총 계수 합은 같으며 활동 지표에 높은 신뢰도나 새 가점을 자동 부여하지 않는다. 이 단계는 종목 순위의 추가 관련성 비교이며 목표 가격 분포를 바꾼 세 가격 예측 모델이 아니다.

원래 과거 작업 전체 완료 및 기존 `coefficient_audit` 원본 재생 완료를 모두 기다린다. 완료된 재생 기록의 방법·정책·표본·기업·가격·사례 해시와 수치를 재구성해 확인한 뒤 새 후보만 계산한다. 기존 512경로 가격 시뮬레이션을 다시 실행하지 않는다. 이전 검사 결과가 실패하거나 의존 자료가 바뀌면 비교를 중지한다.

개발·검증 기업과 기간만 읽으며 마지막 기간·미관측 207기업은 열지 않는다. 동일한 세 후보를 모두 계산할 수 있는 동일 사례끼리 비교하고 누락 분모를 유지한다. 1차 비교값은 기준 종가에서 이후 5거래일 최고가까지의 상승폭으로, 최대 기회이지 실현 수익이 아니다. 2차 비교값은 기존 매수·매도 각각 25bp(각 0.25%) 비용 후 5일 보유 수익이다. 종목 순위 상관은 승률이나 인과효과가 아니다.

날짜별 종목 묶음을 유지하여 후보와 원래 신호의 상관 차이를 계산한다. 최소 날짜별 60기업·16기준일·8개 명목 묶음 조건을 검사하고 기본 4일, 민감도 2/8일 묶음으로 2,000회 재표집한다. 누락 날짜나 시간 표본 부족이 있으면 구간을 보류한다. 여러 후보와 비교값의 개별 탐색 구간이며 다중 비교를 보정한 확정적 우월성 검정이 아니다. 자동 우승 후보 선정·계수 조정·점수 승인은 수행하지 않는다.

## 뉴스 연결 경계

뉴스 최초 공개 시각이 검증되지 않았으므로 현재 모든 보고서의 뉴스 연결은 보류다. `completed_before_event`는 정확한 시각 이전에 종료한 일봉을 고르는 시간 계산 보조 함수일 뿐 기사나 시각의 진위를 확인하지 않는다. 날짜만 있는 발표와 발표 당일의 전체 거래량을 선행 매수 근거로 쓰지 않는다. 과거의 주가 상승을 뒤에 발견한 뉴스의 효과로 인증하지 않는다.

## 예약 실행과 한도

`turnover_job.py`와 `install_turnover_task.ps1`은 기존 네 작업을 바꾸지 않는 다섯 번째 Windows 예약이다. 창 없는 현재 사용자 실행을 15분마다 시도하며 PC 전원과 로그인이 필요하다. 원본 평가와 기존 재생이 끝나면 자동 비교하고 기업별 체크포인트에서 재개한다. 최대 14일/1,000회 중 먼저 도달한 한도에서 중지한다. 한 번에 100기업·600초 예산을 처리 단위 사이에 확인하므로 단일 단위는 예산을 넘을 수 있고 스케줄러 상한은 15분이다.

추가 자료 API·외부 추론·모델 학습·유료 서비스·최종 시험 해제·주문을 실행하지 않는다. 완료·검증 실패·선행 작업 중단은 자체 예약을 비활성화하고 `STATUS.ko.md` 및 필요 시 `INTERRUPTION.ko.md`에 사유와 재개 조건을 남긴다. `--stop` 또는 해당 작업 폴더의 STOP 파일로 중단할 수 있다. 실행 전후 고정 파일과 의존 작업의 무결성을 검사한다.

실제 결과와 고정 방법의 다음 부모 기준선은 `reports/private/turnover_case/20261109/`에 보관한다. 상시 뉴스 수집은 추가하지 않았다. 이 단계의 수용 기준은 계산·누락·미래 차단·동일 계수·원본 재생 연계·중단 복구의 검증이며, 미래 수익성 입증은 별도다.
