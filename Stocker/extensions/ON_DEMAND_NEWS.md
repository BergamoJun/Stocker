# 요청형 최근 N일 뉴스

종목을 입력한 시점에 필요한 최근 기간의 뉴스 링크를 조회한다. 상시 수집·새 예약 작업을 추가하지 않는다. 현재 SEC 식별과 검색 프로파일이 연결된 BE/MSFT/XOM을 지원한다. 기존 72시간 갱신기·아카이브·보고서·모델·다섯 예약 작업은 보존한다.

```powershell
.\.venv\Scripts\python.exe -B -m extensions.ondemand_news --ticker BE --days 7 --baseline <이 범위의 runtime.json>
.\.venv\Scripts\python.exe -B -m extensions.ondemand_news --ticker BE --days 7 --baseline <runtime.json> --offline
.\.venv\Scripts\python.exe -B -m extensions.ondemand_news --ticker BE --days 7 --baseline <runtime.json> --refresh
.\.venv\Scripts\python.exe -B -m extensions.ondemand_news --validate <저장된 실행 폴더>
```

`--days`는 달력 기준 최근 1~30일, 기본 7일이다. `--refresh`는 임시 캐시 재사용만 생략하며 계정 간격·공유 잠금·429 대기·요청 상한을 우회하지 않는다. `--offline`은 신선한 기존 캐시만 사용하며 API 요청은 없다. 두 옵션을 동시에 사용할 수 없다. API 키는 기존 `MASSIVE_API_KEY` 환경변수를 사용하고 콘솔·파일에 저장하지 않는다.

## 수집 범위와 의미

- 회사: 기존 공유 계정 큐를 사용하는 Massive ticker news, 종목 포함 여부와 공급자 게시 표기 기간 검사.
- 업종: SEC에 결합한 기존 기업 프로파일의 업종 검색식.
- 거시·금리, 원자재, 정치·정책: 별도 고정 GDELT 검색식. 일반 맥락 후보이며 해당 기업의 실제 사업 영향으로 인증하지 않는다.
- 한 요청은 최대 회사 1회·GDELT 4회, 검색당 25개 결과다. 페이지를 자동으로 따라가지 않으며 개수 상한이나 제외 기록이 있으면 부분 결과로 표시한다.

GDELT는 명시적인 시작·종료 시각으로 요청하고 기존 공유 예산·15초 간격·429 대기를 사용한다. 동일 요청에서 공급자 실패가 발생하면 이후 GDELT 검색을 보류한다. 실패·대기 결과도 짧게 캐시하여 같은 실패를 반복하지 않는다. 반환 상한 등 부분 링크 결과는 정상 응답으로 취급하되 취재 완료로 표시하지 않는다. [GDELT 기간 인자](https://blog.gdeltproject.org/gdelt-doc-2-0-api-debuts/), [Massive 뉴스 제공 시각과 이력 설명](https://massive.com/knowledge-base/article/how-far-back-does-massives-news-and-sentiment-data-go).

회사 시간은 공급자의 게시 시각 표기이며 독립 확인한 최초 공개 시각이 아니다. GDELT seendate는 색인 관측 시각이며 발행·사건 시각으로 바꾸지 않는다. 기간 필터는 각각 그 시간 필드를 사용한다. 검색 실패는 뉴스 없음과 다르며, 제한 검색의 빈 결과도 세계 전체에 관련 뉴스가 없음을 뜻하지 않는다. 제목·주소·출처·시간만 보관하고 본문·요약·이미지·공급자 감정값은 폐기한다. 어떤 공급자 메타데이터도 AI에 보내지 않는다.

최근 시간 표기 순으로 기사 링크를 보여준다. 이는 중요도·호재·수익률 가점 순서가 아니다. 같은 URL의 중복만 통합하고 모든 출처·주제·시간 표기를 유지한다. 다른 URL의 같은 사건 여부는 아직 판독하지 않는다. 기사별 사람 해석 파일을 요구하지 않으며 사건 영향이 평가됐다고 표시하지 않는다. 뉴스 점수·정식 추천도는 계속 보류한다.

## 조회·재사용 시각

캐시 키에 공급자·주제·검색식·N일·방법/정책 해시를 포함하고 회사 검색에는 CIK·프로파일 수신 기록도 결합한다. 3일 조회를 7일 조회로 재사용하지 않는다. 같은 일반 맥락 검색은 기업 간 재사용할 수 있지만 기업별 영향·사람 검토 승인은 전파하지 않는다.

15분 안의 재사용은 최초 실제 조회·캐시 보관 시각을 유지한다. 새 요청의 검색 종료 시각 이후로 자료를 최신화한 것처럼 표시하지 않는다. 예를 들어 12:00 결과를 12:05에 재사용하면 12:00~12:05는 아직 검색하지 않은 구간으로 표시한다. 새 요청의 N일 범위에서 벗어난 예전 링크는 최종 목록에서 제외한다. 공급자 자체의 수집 지연은 이 구간과 별개이며 실시간성을 보장하지 않는다.

요청 시작 시각, 검색 범위, 실제 수신·최초 보관, 보고서 생성 시각을 구분한다. 받은 자료를 요청 시작 시각에 이미 알았던 정보로 소급하지 않는다. 새 캐시 수신 기록은 보고서 생성 초보다 앞서 있어야 하며, 필요한 경우 최대 약 1초를 기다린다. 보고서에는 사용한 조회 결과의 독립 사본이 들어가므로 이후 캐시 교체·삭제가 과거 보고서를 바꾸지 않는다. 해시 검사는 로컬 변경을 발견하는 수단이며 출처의 사실·시각에 대한 독립 인증이 아니다.

## 저장 용량과 삭제 범위

새 저장소는 `reports/private/on_demand_news/{real|illustrative}/`다. 고정 소유권 파일과 전용 쓰기 잠금을 확인한다. 다른 저장소·별칭 경로·알 수 없는 캐시 파일은 처리하지 않는다.

| 자료 | 상한과 처리 |
|---|---|
| 임시 조회 캐시 | 최대 128개·16MiB, 개별 256KiB. 조회 시 보관 48시간 초과 또는 용량 초과 항목부터 제거하며 최근 접근 자료를 우선 유지 |
| 보고서와 사용 근거 | 최대 1,000건·256MiB, 건당 2MiB. 자동 삭제하지 않고 새 보고서를 만들 공간이 부족하면 API 요청 전 중지 |
| 기존 자료 | 기존 기사 이력·보고서·공시·가격·예약 정의를 삭제하거나 덮어쓰지 않음 |

상한과 15분/48시간은 운영용 초기 설정이며 예측 성능을 최적화한 값이 아니다. 요청이 없을 때 수집이나 정리 작업을 실행하지 않는다. 보고서마다 정상화한 메타데이터·원래 조회 범위와 결과·입력/방법/출력 해시를 보존하고 JSON·한국어 Markdown을 재생한다. 원래 HTTP 전체 응답은 보관하지 않는다. 공급자 반환 원문 해시 또는 파싱 응답 해시를 남기지만 폐기한 본문을 재생할 수 있다고 표시하지 않는다.

## 검증과 한계

기간별 캐시 분리, 재사용 시각·미검색 구간, 공급자 실패 후 중지, 실패 캐시·429 공유 대기, 본문/감정값 배제, 출처·CIK·프로파일·실제/가상 분리, 동일 URL 통합, 임시 자료 정리 후 보고서 재생, 경로·용량·변조·콘솔 오류 보호를 검사한다. Windows 실제 심볼릭 링크 생성 권한이 없으면 해당 실물 시험은 건너뛰고 별칭 경로 검사 자체는 모의 시험으로 확인한다.

현재 이 모듈은 요청형 링크 수집과 근거 저장을 완성하는 단계다. AI 기사 판독·검증된 기업 영향·뉴스 수익 예측·모든 세계 뉴스 취재·전체 투자 보고서 통합을 완료한 것으로 표시하지 않는다. 시장·정책·원자재의 단기 효과는 별도 원문 사용권·정확한 시점·사건 표본과 평가가 필요하다. 신규 학습·유료 API·주문·새 백그라운드 작업은 활성화하지 않는다.

실패·대기 결과의 checked_at은 그 상태를 확인한 시각이며 성공한 기사 수신 시각이 아니다. 최종 실증과 검사는 [완료 보고서](../reports/private/on_demand_case/20261109/SUMMARY.ko.md)에 있다.
