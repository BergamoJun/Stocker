# Priority 1: 반론 모델의 원시 판단과 외부 검사

`critic_v2`는 기존 방법·실패·보고서를 변경하지 않는 새 후보다. 모델은 판단 코드 15개 중 하나만 출력한다. 판정/사유 쌍은 `critic_v2_policy.json`의 관계에서 기계적으로 변환하며 원시 모델의 두 출력으로 표시하지 않는다. 구조상 모순 방지와 의미 판단의 정확성은 다른 결과다.

FACT_VERIFIED는 동일 기업·시점·범위·단위의 정확한 숫자 확인만 뜻한다. 경제적 노출이나 주가 효과의 인증이 아니다. CONDITIONAL은 근거가 맞고 실제 노출이 미확인인 조건부 경로다. UNKNOWN은 충분한 판단 근거가 없는 경우다. 잘못된 사실 ID·출처 종류·기업·시각·방향·기간/범위·출처 누락·중복·충돌·노출 확정·기간 주장·인용 오류는 각각 별도 코드다.

원시 판단을 외부 출처/수치 규칙과 비교하고 어느 쪽이든 승인할 수 없으면 최종 채택을 보류한다. 규칙이 오승인을 차단해도 원시 모델 실패는 남긴다. 같은 Qwen 가중치를 사용하므로 독립 모델 검증이라고 표시하지 않는다. 가격·공급자 메타데이터·정답은 프롬프트 밖에 둔다.

기존 12개는 원래 승인/거부 회귀 기준으로 유지한다. 새 24개는 모델에게 정답을 숨긴 합성 사례다. 입력·정답·순서·방법·임계값을 실행 전에 고정한다. 작성 개발자와 평가 개발자가 같아 독립 사람 판정이나 실제 사건의 눈가림 성능이라고 주장하지 않는다. 잘못된 원시 승인 0건, 정확도 85%, 계약 수용 90%의 기존 기준을 유지하고 회귀/신규 묶음 각각 확인한다. 미실행은 통과가 아니다.

Priority 1의 구현·테스트·실제 모델 상태를 검토한 증거 파일이 있어야 Priority 2의 범위를 선언한다. 이후에도 AI 품질 미달/미실행은 운영 채택을 계속 막는다. Priority 2의 독립 근거 구조 개발은 실패를 보존한 뒤 별도로 진행할 수 있다. 기존 23변수·계수·잠긴 자료·예약 작업에는 연결하지 않는다.
